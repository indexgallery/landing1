# DESIGN INDEX GALLERY

Каталог с PostgreSQL, фотографиями в S3 / Vercel Blob и защищённой админкой. Сохранение публикует изменения без пересборки сайта.

## Локальный запуск

Нужны Docker Desktop с Compose и Node.js 22.16+ (или 24 LTS). В папке проекта:

```sh
npm run setup
docker compose up --build -d
```

setup создаёт .env со случайными паролями и не меняет существующий файл. Зависимости устанавливаются внутри Docker. Первый запуск создаёт таблицы и bucket MinIO, импортирует 74 объекта и фотографии. Это может занять несколько минут.

- Сайт: http://localhost:4173
- Админка: http://localhost:4173/admin.html — пароль ADMIN_PASSWORD из .env.
- Консоль MinIO: http://localhost:9001 — S3_ACCESS_KEY_ID / S3_SECRET_ACCESS_KEY из .env.

MinIO собирается из закреплённого релиза исходников upstream, поэтому первый запуск включает компиляцию и может быть дольше обычного. Если порт 4173 занят прежним сервером, остановите его перед запуском.

```sh
docker compose logs -f init web
docker compose ps -a
docker compose down
```

Повторный запуск не перезаписывает каталог. Данные сохраняются в volumes postgres-data и minio-data. **Не используйте docker compose down -v, если данные нужны.** Порты доступны только с этого компьютера. Compose предназначен для разработки.

## Данные и доступ

catalog_state.payload хранит снимок каталога, категорий и настроек в JSONB с номером версии. Вся публикация атомарна. Таблица media хранит ключ, URL, MIME-тип, размер и дату загрузки фото.

Фото загружаются прямо в S3/Blob, без base64 в JS. Старые JSON с base64 поддерживаются: редактор загружает их фото перед сохранением. Удаление фото из карточки не удаляет файл физически — старые резервные копии продолжают работать. Очистка неиспользуемых файлов пока ручная.

Вход: общий пароль и подписанная HttpOnly-сессия на 8 часов. Есть проверка Origin и ограничение попыток входа в PostgreSQL. Индивидуальные аккаунты и роли пока не предусмотрены. Устаревшая вкладка не может перезаписать изменения другого редактора.

Сохранение публикует изменения сразу. Уже открытая страница посетителя получает их после обновления. Предпросмотр текстов меняется при вводе, до сохранения.

## Vercel: Neon + Blob

В Vercel работают сайт и API. База и хранилище — облачные сервисы; контейнеры Compose туда не переносятся.

```sh
npm ci
npx vercel login
npm run vercel:setup -- --origin https://YOUR-PROJECT.vercel.app --scope YOUR-TEAM
```

Скрипт проверяет вход, предлагает связать проект, подтягивает production-переменные, создаёт недостающие Neon/Blob, задаёт секреты, выполняет миграцию и импорт. Выбор тарифа и условия сервисов могут потребовать действий в терминале/браузере. Он создаёт реальные ресурсы — запускайте в аккаунте заказчика.

При ошибке создания отметка сохраняется в .vercel/catalog-setup.json. Повторный запуск просит проверить и подключить существующий ресурс вместо создания второго.

Для импорта с компьютера нужен BLOB_READ_WRITE_TOKEN. Если Blob подключён только через OIDC, добавьте токен хранилища в production-переменные и повторите запуск. Пароль администратора будет в игнорируемом .env.vercel.local с правами 0600. Не передавайте этот файл целиком.

После проверки:

```sh
npx vercel --prod --scope YOUR-TEAM
```

Либо добавьте --deploy к vercel:setup. Облачные ресурсы и production-deploy в рамках этой правки не запускались. APP_ORIGIN должен совпадать с публичным адресом сайта; при смене домена обновите его. Preview требует своей базы/Blob и APP_ORIGIN. Не подключайте preview к production-базе.

## Собственное S3

Настройки перечислены в .env.example: DATABASE_URL (для Neon — pooled URL с sslmode=require), APP_ORIGIN, ADMIN_PASSWORD (12+ символов), SESSION_SECRET (32+), STORAGE_DRIVER=s3 и S3-переменные. Для AWS endpoint можно оставить пустым и указать S3_FORCE_PATH_STYLE=false. Для MinIO/R2 укажите endpoint провайдера. S3_PUBLIC_ENDPOINT — адрес для браузера, S3_PUBLIC_URL — публичная база URL фотографий.

Bucket должен разрешать публичное чтение фото и CORS для APP_ORIGIN: GET/HEAD/PUT, AllowedHeaders ["*"], ExposeHeaders ["ETag"]. Запись закрыта: админ получает краткосрочную подписанную ссылку. Скрипт не меняет production-политику bucket.

После настройки ключей выполните scripts/migrate.mjs и scripts/seed.mjs с нужным env-файлом, затем deploy. Например: node --env-file=.env.cloud scripts/migrate.mjs. Не запускайте их с локальными ключами против production.

Локальные URL localhost:9000 в production не работают. Для облака выполняется отдельный первоначальный импорт из исходных файлов. JSON из локального редактора не копирует сами файлы между хранилищами: новые локальные фото при таком переносе нужно скопировать отдельно и заменить URL.

## Проверки и обслуживание

Полные интеграционные тесты на Python запускаются одной командой:

```sh
python3 scripts/test_integration.py
# или npm run test:integration
```

Нужны Python 3.10+ и запущенный Docker Desktop. Зависимости Python установятся внутри тестового образа; на компьютер ничего через pip ставить не нужно. Скрипт создаёт отдельный Compose-проект со случайным именем, без портов на хосте, без рабочего .env и без общих volumes. Поднимает настоящий PostgreSQL и MinIO, импортирует каталог, запускает HTTP-тесты API и S3, затем проверяет сохранность данных после повторного seed и перезапуска API. В конце удаляет только свои тестовые контейнеры и volumes, в том числе при ошибке. При сбое возвращает ненулевой exit code и показывает логи. Для медленного первого запуска: --startup-timeout 600.

Проверяются публичные страницы, соответствие API и PostgreSQL, доступность импортированных фото, создание/изменение/удаление объекта, категории, тексты, конфликт версий, прямая подписанная загрузка в S3, CORS, метаданные, вход/выход, поддельные cookies, Origin, лимит попыток входа, валидация и закрытость исходников сервера. Эти тесты используют реальные сервисы, без pg-mem и моков.

```sh
npm ci
npm test
npm run build
```

Тесты используют pg-mem и локальный тестовый HTTP endpoint S3: вход, сохранение, категории, конфликт версий, метаданные и ограничения. Они не заменяют запуск настоящего Docker и облачных интеграций.

Сборка помещает только разрешённые публичные файлы в public/. Серверный код, .env и репозиторий не раздаются.

Резервировать нужно **и PostgreSQL, и файлы S3/Blob**. JSON из админки содержит ссылки на фото. Инструкция: [ADMIN-GUIDE.md](ADMIN-GUIDE.md).

Не запускайте scripts/build_catalog_data.py поверх клиентских правок. catalog-data.js и site-data.js используются только при первом импорте. Повторный seed существующий каталог не меняет; дальнейший источник данных — PostgreSQL.

## Локальные изображения

Все исходные картинки собраны в img/ с сохранением структуры подпапок; папка добавлена в .gitignore. Для локальной сборки и первоначального импорта она должна присутствовать. На чистом клоне Git её не будет: перед первым импортом передайте img/ отдельно либо выполните первоначальный импорт с компьютера, где изображения есть. После заполнения базы и S3 сайт на Vercel собирается без img/ и получает фотографии из хранилища. Новые изображения загружаются через админку. Картинка раздела контактов также включена в перенос в S3.
